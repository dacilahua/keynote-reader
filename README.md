# Keynote Reader 1.1.1 · 文稿阅读版

将 `.key` 文件拖入窗口，选择字号和版式，再点击“导出阅读版 PDF…”。也可以用“选择 Keynote…”按钮打开文件。应用已编译，可直接双击 `Keynote Reader.app`，无需 Python、Node 或开发工具。可将应用复制到“应用程序”文件夹。

## 1.1.1：更适合屏幕阅读

默认使用“屏幕清晰”：幻灯片最长边 1600 像素、JPEG 质量 76%；“更小文件”为 1200 像素、质量 60%。图像压缩逐页完成，不把整份文稿同时展开为大图。演讲者注释始终用矢量文字排版，清晰且可复制。

当单页原始矢量 PDF 比压缩图片更小时，会自动保留矢量页。另有“原画质”选项，保留与 1.0 版相同的幻灯片内容。图片化的幻灯片内部文字不能选择或搜索，极小文字放大后会有像素感；需要细看密集表格时选择原画质。

图像压力测试中，同一页从 11,513,540 字节变为推荐模式 331,412 字节（约减少 97.1%），更小文件模式 147,210 字节（约减少 98.7%）。这是专门制作的 3200×1800 高分辨率纹理测试素材，不是用户业务原稿；实际压缩率依赖图片数量、复杂度及重复资源，不保证每份文稿相同。

应用已加入完整 macOS 多尺寸图标。发布目录中的 macOS ZIP 供转发安装，源码 ZIP 供维护和重新构建；应用运行不需要开发环境。

## 版式

- **紧凑阅读**：默认选项。大图在上、注释在下，页高随内容收缩，最长不超过 A4。适合屏幕阅读与发送他人。
- **固定 A4**：页面均为 A4 纵向，适合打印，因此短注释页仍会有空白。
- 注释字号可选 11、13、15、18 磅，默认 13 磅。长注释自动续页，续页不重复放大图。
- 幻灯片保持完整比例；原幻灯片内部自带的空白不会自动裁切。竖版幻灯片会按高度上限缩放。
- **自动排除 Keynote 中设为“跳过”的幻灯片及其注释。** 其余页面按原顺序连续编号；全部页面均跳过时会提示没有可导出的内容。
- 读取的是“演讲者注释”，不是协作批注。注释按纯文本统一排版，不保留原注释中的颜色、加粗等富文本样式。文字不经过 OCR，不从幻灯片 PDF 反向复制。

## 本地处理与权限

应用复制你选择的文稿到临时目录，通过本机 Keynote 打开副本、读取注释并导出最高图像质量的 PDF，再按所选画质处理幻灯片，由 macOS 的 Core Graphics/Core Text 排版。原始文稿不会被修改；已经打开的原稿窗口不会被关闭。请先保存原稿，工具处理的是磁盘上已保存的版本。

应用没有网络请求、账号或云端服务。输出 PDF 保存在你选择的位置。正常完成或报错后删除导出的临时副本；若进程被强制结束，系统临时目录中可能残留 `KeynoteReader-*` 文件夹。内置测试会保留 `ReaderFixture-*` 测试文稿供再次导出。

首次导出时，macOS 可能询问是否允许本应用控制 Keynote，请允许。若曾拒绝，可到“系统设置 → 隐私与安全性 → 自动化”开启对应权限。文件在“桌面”“文稿”“下载”等受保护目录时，系统也可能提示文件夹访问。工具本身不需要辅助功能、录屏或完全磁盘访问权限。

权限位置参考：[Apple：允许 App 自动化并控制其他 App](https://support.apple.com/en-nz/guide/mac-help/mchl108e1718/mac)。

这是本地临时签名版本，**没有 Apple Developer ID 签名和公证**。本机已成功打开；通过网络传到其他 Mac 后，系统可能阻止首次打开。如果你确认使用的是本次交付的应用，可按 [Apple 官方说明](https://support.apple.com/en-au/102445)在“隐私与安全性”中为此应用选择“仍要打开”。不需要关闭全局安全保护。

## 兼容性与边界

- 构建目标为 **macOS 13 或以上**，包含 `arm64` 和 `x86_64` 两种架构。实际还须满足所安装 Keynote 的系统要求。
- **已实测**：本机 Apple 芯片、系统报告 macOS 27.0.1、Keynote Creator Studio 15.2.1。
- **尚未实测**：Intel Mac、macOS 13–26、旧版独立 Keynote。程序兼容两种 Keynote 应用标识并提供标准安装路径回退，但不同版本的导出行为仍需验证。
- 必须安装 Keynote，并能正常打开所选文件。iCloud 文件需先下载至本机。
- 缺失字体、加密文稿、文件损坏或 Keynote 弹窗可能阻止导出。先在 Keynote 中处理提示，再重试。加密文稿不属于本版已验证范围。
- 原画质模式保留 Keynote 导出的矢量图文，屏幕模式按上述设置压缩；无法恢复原图本身不存在的细节。动画、视频和音频在 PDF 中不会播放，每张幻灯片只导出一个静态状态。
- 大型文稿需要额外磁盘空间和内存，Keynote 操作超时为 10 分钟。进行中请不要强制退出本应用或 Keynote。此版尚无中途取消按钮。
- 输出前核对幻灯片与注释数量，数量不一致时停止，避免错页。已有目标 PDF 仅在完整生成成功后原子替换。

## 本次验证

1. 1.1.1 回归文稿包含 5 张幻灯片：首部、中间、末尾各一张跳过页，以及短注释、55 段长注释两张正常页。跳过页的标题和注释均带有专用标记。
2. 验证只导出两张正常幻灯片及其注释，长注释续页后共 5 页 PDF。检查跳过页标记完全不存在，正常幻灯片与注释对应，55 段各出现一次。
3. 全部跳过时，在导出前终止并提示没有可导出的内容，不覆盖已有输出。
4. 另行验证纯空白注释、600 次长文本、中文、emoji、组合音符、制表符、CR/LF 换行。两种版式均导出 12 页；去除页眉页脚、忽略排版空白并统一 Unicode 规范形式后，全文与输入一致；固定 A4 模式全部页面尺寸一致。
5. 两种架构均编译成功，应用代码签名完整性校验通过。真实原稿、大型文稿、密码文稿及全部历史系统版本未做实测。

测试素材均为专门创建的文稿，不含你的业务原稿。早期的 `测试文稿.key` 与 `测试文稿-阅读版.pdf` 仅作为历史样例；1.1.1 的跳过页回归结果为 `跳过页测试-阅读版.pdf`。

## 源码与重新构建

源码位于 `Source/main.swift`；窗口为 AppKit，注释通过 NSAppleScript 提取，PDF 使用 Core Graphics 与 Core Text 排版，无第三方依赖。

安装 Apple Xcode 或相应命令行开发工具后，在终端执行：

```bash
cd "/路径/KeynoteReader/Source"
./build.sh
./test.sh
```

`build.sh` 构建两种架构并临时签名。`test.sh` 在自己的临时目录运行排版回归测试并自动清理。真实 Keynote 测试通过应用菜单执行，以应用身份请求自动化权限；命令行的系统权限与应用身份不同。

也提供命令行接口，适合已有自动化权限的环境：

```bash
"Keynote Reader.app/Contents/MacOS/KeynoteReader" --export "/路径/文稿.key" "/路径/阅读版.pdf"
```

命令行默认使用紧凑模式、13 磅字号与屏幕清晰画质。添加 `--small` 使用更小文件，添加 `--original` 使用原画质。`--compose` 接口接收幻灯片 PDF、JSON 字符串数组和输出路径，用于独立测试排版；不需要 Keynote。

## 打包与图标

`Source/release.sh` 重新构建并生成安装 ZIP 和源码 ZIP，同时记录 SHA-256。安装 ZIP 中只包含应用、安装说明、使用说明和指向 Applications 的快捷方式，不包含测试文稿或开发工具。对方解压后拖动应用即可。普通用户无需管理员安装脚本。

当前构建环境无法访问磁盘映像服务，因此本次不提供 DMG。在可使用磁盘管理服务的普通 Mac 上，可执行 `./release.sh --dmg` 额外生成 DMG。

图标源图为 `Source/Assets/AppIcon.png`，通过内置图像生成工具制作。设计提示：蓝绿渐变圆角方形底板，象牙白纸页，上方山形与太阳代表幻灯片，下方三条深蓝文字线代表讲稿；无文字、透明外围。`icon.sh` 可将源图重新封装为多尺寸 ICNS，需要系统 sips 与 Python 3；常规构建直接使用已附带的 ICNS，无需 Python。

当前为临时签名发行包，无法提供“已识别开发者、首次无拦截”的公证安装体验。若未来需要公开发行，须由持有 Apple Developer ID 的发布者签名并提交 Apple 公证，再分发；不需要把开发者凭据交给本工具。
